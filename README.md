# carsystem — نظام حجز صيانة سيارات إلكتروني 🚘

نظام كامل (واجهة موقع + لوحة تحكم) لورش صيانة السيارات: العميل يحجز موعده أونلاين
بنفسه، الإدارة تتابع الحجوزات وتحدّث حالة كل سيارة، والتقارير تحسب الإيرادات تلقائياً.

---

## ✨ المميزات

### للعميل (الموقع العام)
- **حجز إلكتروني في 4 خطوات** بدون تسجيل: اختيار الخدمة ← اليوم والموعد ← بيانات السيارة ← التأكيد.
- **مواعيد حقيقية فقط**: النظام يحسب المتاح حسب ساعات العمل، مدة الخدمة، وعدد السيارات
  التي يمكن استقبالها في نفس الوقت (سعة الآليات) — ويستبعد الحجوزات القائمة وأيام الإغلاق.
- **رقم حجز مرجعي** (مثال `CR-260910-A3K9`) لتتبع حالة السيارة في أي وقت من صفحة «تتبع حجزك».
- **صفحة تأكيد** بتفاصيل الموعد + شريط مراحل الحجز + سجل التحديثات + إمكانية الطباعة.
- روابط واتساب واتصال سريع، وتصميم عربي RTL كامل متوافق مع الجوال.

### للإدارة (لوحة التحكم)
- **لوحة تحكم** بإحصائيات اليوم والأسبوع والإيراد الشهري ونسبة الإنجاز، وجدول اليوم
  مع إمكانية تغيير حالة أي حجز بضغطة واحدة.
- **إدارة الحجوزات**: فلاتر بالحالة والتاريخ والبحث (اسم/هاتف/لوحة/مرجع)، تعديل الموعد
  والسعر النهائي، تعيين الفني المسؤول، ملاحظات داخلية، وسجل زمني لكل تغيير حالة.
- **إنشاء حجز يدوي** من الاستقبال للعملاء الهاتفيين (بنفس منطق المواعيد).
- **العملاء والسيارات**: ملف لكل عميل بسياراته وسجل صيانته وإجمالي مدفوعاته وملاحظات داخلية.
- **الخدمات والأسعار**: إضافة/تعديل/تعطيل الخدمات، والمدة والسعر يظهران للعميل فوراً.
- **التقارير**: إيرادات شهرية (6 أشهر)، أداء كل خدمة، توزيع حالات الحجوزات، متوسط قيمة الحجز.
- **تصدير Excel/CSV** لكل الحجوزات (يفتح بالعربية مباشرة).
- **المستخدمون**: إضافة فنيين/موظفين بصلاحيات (مدير نظام / موظف)، تعطيل الحساب، إعادة كلمة المرور.
- **الإعدادات**: اسم الورشة، الهاتف، واتساب، العنوان، ساعات العمل، مدة الفترة، سعة الاستقبال،
  أيام الإغلاق، والملاحظة التي تظهر للعميل مع المواعيد.

## 🧱 التقنيات

| الطبقة | التقنية |
|---|---|
| الواجهة والخادم | Next.js 16 (App Router, Server Actions, Server Components) |
| اللغة | TypeScript |
| التنسيق | Tailwind CSS v4 + خط Cairo (RTL كامل) |
| قاعدة البيانات | PostgreSQL 17 عبر `pg` مباشرة (بدون ORM) |
| المصادقة | NextAuth v5 (Auth.js) — Credentials + JWT |
| التحقق | Zod على الخادم لكل مدخلات النماذج |
| النشر | Docker + Docker Compose + Caddy (HTTPS تلقائي) |

## 🚀 التشغيل محلياً

```bash
# 1) الحزم
npm install

# 2) قاعدة البيانات (ينشئ المستخدم والقاعدة ويطبّق المخطط والبيانات الأولية)
npm run db:setup
#    بيانات تجريبية للعرض:
SEED_DEMO=true npm run seed 2>/dev/null || SEED_DEMO=true node scripts/seed.js

# 3) الإعدادات
cp .env.example .env      # عدّل DATABASE_URL و AUTH_SECRET

# 4) التشغيل
npm run dev
```

ثم افتح: <http://localhost:3000> — ولوحة التحكم على <http://localhost:3000/login>

### حساب المدير الافتراضي
| البريد | كلمة المرور |
|---|---|
| `admin@carsystem.local` | `Admin@12345` |

> ⚠️ غيّرها فوراً في الإنتاج (من صفحة المستخدمين أو عبر `.env` قبل أول تشغيل).

### أوامر مفيدة

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | تشغيل بيئة التطوير |
| `npm run build` && `npm start` | نسخة إنتاجية محلياً |
| `npm run db:migrate` | تطبيق مخطط قاعدة البيانات |
| `npm run db:seed` | إدخال الخدمات والمدير (`SEED_DEMO=true` لبيانات تجريبية) |
| `npx tsx scripts/smoke-test.ts` | اختبار تكاملي كامل على قاعدة بيانات حقيقية |

## 🔐 ملاحظات أمنية

- كلمات المرور مُشفّرة بـ bcrypt (10 جولات) ولا تُخزَّن كنص.
- كل استعلامات SQL تستخدم **معاملات مُربوطة** (لا حقن SQL).
- كل مدخلات النماذج تُتحقق على الخادم بـ Zod (لا نثق بتحقق المتصفح).
- الجلسات موقّعة بـ `AUTH_SECRET` وصلاحية 7 أيام.
- صفحات `/admin/*` محمية على مستوى الخادم (redirect لصفحة الدخول).
- في Docker: قاعدة البيانات لا تنشر أي منفذ للخارج، والوصول لها داخلي فقط.
